# Security Policy

## Supported versions

Security fixes are applied to the current default branch. This reference project does not currently maintain multiple supported release lines.

## Report a vulnerability privately

Do not disclose vulnerability details in a public issue, discussion, pull request, commit, or fork.

If GitHub private vulnerability reporting is enabled, use **Security > Report a vulnerability** in this repository. A maintainer can then coordinate privately through a repository security advisory.

If that option is unavailable, use a professional contact channel listed on the maintainer's GitHub profile only to request a private reporting method. Do not include exploit details, credentials, sensitive logs, or proof-of-concept code in that initial contact.

Include the affected file and revision, impact, reproduction conditions, and a minimal sanitized proof of concept after a private channel is established. Never send real credentials or customer data.

## Scope

Relevant reports include path-containment bypasses, permission escalation, credential exposure, unsafe execution in fork contexts, supply-chain weaknesses, or validation-policy bypasses. General feature requests and non-security defects belong in ordinary issues without sensitive details.

Maintainers should acknowledge a private report, validate impact, agree on a disclosure plan, and publish a fix before public technical details when practical. No fixed response time is promised.
